# 읽은 자료와 구현 연결

## 현재 게임 규칙

[공식 게임 안내](https://play.tetris.com/games/)의 공개 점수·키 표를 확인했다.
일반 1/2/3/4줄은 100/300/500/800, full T스핀 0/1/2/3줄은 400/800/1200/1600,
B2B는 해당 득점의 50% 추가다. 드롭 거리는 별도 계산하고 레벨을 계산 인자로 둔다.
표에 없는 콤보·PC 추가 점수와 미니 점수는 현재 프로필에 임의로 추가하지 않는다.
C HOLD, Space 하드드롭, 화살표 이동, ↑/Z 회전은 공개 기본 키이며 사용자가 변경한 키까지 확인한 것은 아니다.

[현재 게임](https://play.tetris.com/)의 iframe 버전은 `ed6ac6050d45`였다.
실행 스크립트 직접 조회는 403/브라우저 차단으로 실패했다. 따라서 현재 버전의 SRS 벽차기,
미니 판정·고정 지연 일치는 실게임 미검증이다. 다른 게임의 고정 지연이나 PC 보너스를 자동 확정하지 않는다.

## 본문에서 읽은 내용과 적용 범위

| 자료 | 확인한 핵심 내용 | 적용 |
|---|---|---|
| [빌드 정리](https://hse30.tistory.com/73) | 게임별 전용 빌드와 기초 지형·피네스 구분 | 목차를 실행 데이터나 학습 결과로 취급하지 않음 |
| [평평하게 쌓기](https://hse30.tistory.com/122) | 확인된 NEXT, 여러 깊은 우물·특정 미노 의존·구멍 방지 | 높이·매몰 구멍·굴곡·여러 우물·탑아웃 위험 평가 |
| [빠르게 놓기](https://hse30.tistory.com/127) | 양방향 회전, 이동·회전 순서와 DAS 입력 보존의 차이 | 단타 입력 그래프의 짧은 경로, 확인 즉시 키 해제. DAS 보존 전체를 구현했다고 주장하지 않음 |
| [T스핀 기초](https://hse30.tistory.com/82) | 마지막 회전·세 모서리 조건과 미니/싱글/더블/트리플, 대전용 공격표 | 실제 경로·모서리 검사. 공격량을 점수로 쓰지 않음 |
| [TKI](https://hse30.tistory.com/65) | 빠른 I, HOLD한 T, 좌우 대칭과 여러 후속 지형 | 기존 명시 순서 7단계와 대칭만 사용. 단계별 보드·HOLD·회전 경로 검사 |
| [TKI 이후 PC](https://hse30.tistory.com/387) | 특정 순서·확률 조건과 PC 실패 후 후속 안정화 | 확률을 확정 미래로 바꾸지 않음. 확인된 큐만 PC 탐색 후 일반 득점 탐색 |

TKI 기준은 기존 `data/openers/TKI_Fonzie.json`이다. 단계 전후 보드와 HOLD 조건을 검사하며
마지막 T는 full T스핀 경로도 검사한다. 자동 선택은 남은 단계의 블록을 현재/HOLD/확인된
NEXT로 모두 설명할 수 있어야 한다. 보이는 NEXT가 짧으면 개막을 선택하지 않는다.
진행 중 순서·보드가 다르면 빌드를 강행하지 않는다.

LST/ST 전체 분기나 글에 열거된 모든 개막·PC 해법을 새로 구현·학습한 것은 아니다.
개막 이후는 현재 보드·확인된 큐에 대한 일반 점수·PC 탐색이다. 신경망 학습이나 게임 내부 상태 조회도 사용하지 않는다.

## 점수의 의미

예상 점수는 공급한 레벨과 모델 상태에 대한 계산값이다. 실제 점수판을 읽은 값이 아니다.
Auto를 중간에 켠 경우 B2B·콤보 이력을 확정하지 않는다.
T스핀 공개 점수표와 해당 게임의 실제 판정 일치 여부는 구분한다.
PC는 줄 삭제 후 보드 전체가 비었는지 검사하며 미확인 추가 보너스를 붙이지 않는다.
공격량·지형 효용값·예상 점수·실제 점수는 별개다.
