# Tetris Auto

실행: `dist/TetrisAuto.exe` 또는 `run_windows.bat`. 게임 찾기 후 게임을 시작/재개하고 F6을 누릅니다. F8은 긴급 중지입니다. HOLD는 C, 시계 회전은 위 방향키, 하드드롭은 Space입니다. 기본 모드는 continuous입니다. 기존 설정도 최초 실행 시 continuous로 전환합니다.

일반 Auto의 목표는 퍼펙트 클리어(고정 블록이 하나도 없는 보드)입니다. TKI 점수 오프너에 자동 진입하지 않습니다. 별도로 선택하는 오프너 모드와 기존 TKI 데이터는 유지하며, 그 모드의 기본 Auto/HOLD/NEXT 검증 조건도 그대로 적용합니다.

현재 블록과 검증된 NEXT 한 개, 사용 가능한 HOLD만 탐색합니다. 확인된 퍼펙트 클리어 경로는 예상 점수가 더 높은 다른 배치보다 우선합니다. 높은 보드에서 여러 수를 기다려야 하는 경로는 기존처럼 생존 판단에 양보합니다. 경로를 찾지 못하면 줄 삭제를 보상하고 남은 블록 수, 구멍, 덮인 깊이, 최고 높이와 울퉁불퉁함을 줄입니다. 우물을 남기기 위해 탑을 쌓는 보상은 사용하지 않으며, 예상 게임 점수는 표시용으로 계산하고 배치 선택 보상에는 넣지 않습니다. 확인되지 않은 퍼펙트 클리어 점수 보너스도 추가하지 않습니다.

짧은 실시간 예산 안에서 PC 경로는 회전·수평 이동·하드드롭으로 만들 수 있는 후보를 먼저 검사합니다. 이 검색은 모든 끼워 넣기 경로를 증명하는 완전 탐색이 아니며 `pc_route_scope=rotation_translation`으로 기록합니다. 경로가 없다는 결과는 관측한 큐와 검사한 후보 범위 안에서 찾지 못했다는 뜻입니다. NEXT 한 개로 먼 미래의 PC를 보장할 수는 없습니다.

낙하가 빨라지는 후반의 긴급 탐색도 같은 낮은 보드 평가를 사용합니다. 제한된 시간 안에서 짧은 이동과 회전을 먼저 검사하고, 실제 관측 중력과 입력 확인 시간을 반영해 끝낼 수 있는 경로만 제안합니다. 안전한 경로가 없거나 인식이 불확실하면 기존 재탐색·키 해제·실패 제한·중지 조건을 따릅니다. 멈춤 방지를 위해 안전 조건을 완화하지 않습니다.

후반에 현재 블록의 전체 경로 검사만으로 예산을 소진하지 않도록, PC 목표의 일반 탐색도 회전·수평 이동·하드드롭 후보와 폭 4의 빔 탐색을 사용합니다. 관측한 NEXT 한 개까지 평가할 기회를 확보하려는 제한 탐색이며, 모든 끼워 넣기나 T-Spin 경로를 포함하지 않습니다. 현재 블록의 입력 시간 검사와 홀드 확인 시간도 후보 선택 전에 검사합니다. HOLD 확인 시간은 이동 확인 시간과 별도로 전달하며, 실제 HOLD 이후에도 새 관측으로 기존 제어 검사를 수행합니다.

일반·긴급 탐색 모두 다음 블록의 낙하 공간이 입력 확인 세 번을 수행할 시간보다 짧아지는 배치에 평가상 불이익을 줍니다. 이는 관측한 중력·입력 지연을 이용한 예방적 휴리스틱이며 안전 판정을 대신하지 않습니다. NEXT가 없으면 일곱 블록 중 가장 짧은 낙하 공간을 보수적으로 계산하고 순서를 추측하지 않습니다. 안전 경로 미발견은 `execution_window_failed`, 최종 중지는 원래 사유를 포함한 `controller_stop` 이벤트로 기록합니다. 연속 5회·블록당 8회 실패 시 중지하는 조건과 기존 표시 문구는 유지합니다.

메인 화면은 Auto 실행에 필요한 게임 찾기 / Auto 시작·중지 / 중지 / 설정으로 정리했습니다. 입력·프리뷰·영역 진단과 JSON 가져오기는 고급 메뉴에 있습니다. 화면의 전략과 확인된 배치 수는 실제 화면 피드백을 따릅니다. 화면 인식 실패 시 입력을 중지하는 기존 동작은 유지합니다.

## 조사한 자료

- https://four.lol/openers/tki/ : 이른 I, 첫 가방 TSD, Fonzie 및 낮은 보드에서 후속 전개. 좌표 데이터는 기존 `data/openers/TKI_Fonzie.json`을 재사용하며 새 그림을 복제하지 않았습니다.
- https://www.tetriseffect.game/beginners-community-guide/ : 9-0 우물, 평탄 쌓기, 다운스택에서 삭제 이후 지형 고려, T-Spin의 회전/코너 조건.
- https://howtotetris.com/basic-and-practical-openers/ : 오프너 큐 조건과 중반 전략 전환. 이번 버전은 DT Cannon/PCO를 실행 데이터로 추가하지 않았습니다.

실게임 입력 성공과 모델 시뮬레이션 성공은 별도로 확인해야 합니다. 브라우저 도구로 직접 보낸 입력은 Tetris Auto의 입력 검증 결과가 아닙니다.

2026-10-27 오프라인 비교: 같은 세 가지 7-bag 순서에서 NEXT 한 개, 매 수 60ms 예산으로 기존 점수 목표와 PC 목표를 각각 80수 재생했습니다. 모두 80수 경로·착지 검증을 통과했고 최고 높이는 기존 7/8/9칸, PC 목표 6/7/6칸이었습니다. 이 무작위 비교에서 PC는 양쪽 모두 0회였습니다. 별도 두 O 블록/HOLD 사례는 빈 보드까지 경로를 재생했습니다. 이 결과는 실제 게임 후반 끊김 해결이나 PC 성공률의 증거가 아닙니다.

같은 날 후반 보완 검증: 실제 저장 기록 `20261027_115723`의 seq5154 보드를 입력한 결정 테스트에서 기존 5칸 배치 대신 높이 4칸 이하·구멍 0의 경로를 선택하고 독립 입력 시간 검사를 통과했습니다. 시계 고정 테스트이므로 속도 측정은 아닙니다. 별도 모형(중력 12칸/초, 이동 확인 180ms, HOLD 확인 300ms, 화면 나이 70ms, NEXT 한 개) 세 순서에서 각 60수의 제안 경로 검사를 통과했습니다. 모형의 PC는 모두 0회이며 실제 게임에서 후반 끊김 해결 여부는 미검증입니다.

이동 속도 보완: 이동·회전의 화면 ACK를 확인한 프레임에서 남은 경로와 입력 조건을 다시 검사해 다음 키를 준비합니다. 키 간격이 아직 남아 있으면 그대로 기다리고, 간격이 끝났을 때도 같은 관측이 신선하고 이전 입력의 ACK가 끝난 경우에만 재검사합니다. 새 탐색 결과도 아직 신선한 관측을 사용할 수 있습니다. 새 관측 도착은 제어 루프에 즉시 알려 주며, 입력을 확인하지 않고 여러 키를 묶어 보내지는 않습니다. HOLD·드롭의 두 번 확인, 키 누름/간격 설정, 프레임 나이·중력 경로 검사·중지 조건은 유지합니다.

후반 평가에서는 다음 블록의 조작 여유 부족을 입력 확인 주기 단위로 계산하고 제곱 불이익을 더합니다. 중앙 탑을 만들수록 다음 수의 조작 공간을 급격히 잃는 상황을 평가하기 위한 휴리스틱이며 안전 게이트가 아닙니다. 실제 `20261027_143409` 세대 247 보드를 재생한 검사에서는 중앙 13칸 배치 대신 오른쪽 이동 후 12칸 배치를 선택하고 기존 경로 시간 검사를 통과했습니다.

동일한 지연 화면 모형(50ms 캡처 주기, 40ms 처리 지연, 키 누름/간격 각각 35ms, NEXT 한 개, 중력 없음)에서 동일 75회 키 입력·20개 배치의 모의 시간은 기존 9.450초→7.655초였습니다. 이는 불필요한 대기 감소를 확인한 모의 결과이며 실제 게임 속도나 후반 생존 개선을 확인한 결과는 아닙니다.
